# Windows: Authenticode signing

Unsigned Windows builds trigger SmartScreen ("Windows protected your PC") until the file has built up
reputation. A code-signing certificate removes the "unknown publisher" part; with an **EV** certificate (or
Azure Trusted Signing / SignPath) SmartScreen trust is immediate, with a normal OV certificate it builds up over
time.

## What the workflow does today

Job `windows` in `.github/workflows/release.yml`, step *Package*. Runs only when the secrets exist:

| Secret | Value |
|---|---|
| `WINDOWS_CERT_PFX` | base64 of a `.pfx` code-signing certificate (`[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx"))`) |
| `WINDOWS_CERT_PASSWORD` | its password |

Without them everything stays unsigned (as before). With them `signtool sign /fd sha256 /tr <RFC 3161 server>
/td sha256` signs, and `signtool verify /pa` checks, these files:

* `Aurora.exe`, `aurora-rdp.exe`, `aurora-web.exe` (before they are packed into the **portable zip** and before
  Inno Setup embeds them in the **installer**, so the installed files are signed too),
* the installer `Aurora-<version>-windows-x64-setup.exe`.

Review notes: the RFC 3161 timestamp (`/tr` + `/td sha256`) was already present; it now falls back to a second timestamp
server (Sectigo) when DigiCert is unreachable, every signature is verified right after signing, and a failure
stops the job (a signed release never silently contains an unsigned file). Not signed: the uninstaller
(`unins000.exe`, generated by Inno Setup; signing it needs `SignTool=` in `aurora.iss`) and the `.zip` itself
(zips cannot be signed; the checksum signature covers it).

## Getting a certificate

| Option | Cost | Notes |
|---|---|---|
| **SignPath Foundation** (signpath.org/foundation) | free for open-source projects | Application on their site; they sign from your GitHub Actions run via the `SignPath/github-action-submit-signing-request` action and an API token (no private key in your repo). Requires a public repository with an OSI license (Aurora: MIT), a build that runs on GitHub-hosted runners, and published signing policy. Certificate in the name "SignPath Foundation". Would replace the `Sign` function with an upload of the unsigned artifact |
| **Azure Trusted Signing** (Artifact Signing) | about 10 USD/month | Microsoft-managed certificates, immediate SmartScreen reputation, no hardware token. Needs an Azure subscription and identity validation (individuals and organizations in some countries). Use `azure/trusted-signing-action` with a service principal in secrets |
| Classic OV/EV certificate (Sectigo, DigiCert, …) | 100–500 USD/year | Since 2023 private keys must live on hardware (HSM/token or cloud HSM), so a plain `.pfx` secret is only possible with providers that still export it or via their cloud-signing APIs. `WINDOWS_CERT_PFX` works with any `.pfx` you have |

If you pick SignPath or Azure the existing `WINDOWS_CERT_PFX` hook can stay (it simply stays off); replace the
`Sign` function body with the respective action's call.

## Verify a signed file

```powershell
Get-AuthenticodeSignature .\Aurora-<version>-windows-x64-setup.exe | Format-List
signtool verify /pa /v .\Aurora.exe
```
